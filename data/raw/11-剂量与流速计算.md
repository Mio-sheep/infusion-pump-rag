# 剂量与流速计算

这一篇讲"医嘱上的剂量率"怎么变成"泵上的 mL/h"。
仓库里配了一个能跑这个计算的工具，见最后一节。

## 为什么这件事值得单独写一篇

因为这是**十倍级差错**最高发的地方。三个原因叠加：

1. 单位换算链长：μg/kg/min → μg/h → mL/h，中间要乘体重、乘 60、除浓度，
   任何一步看错单位，结果差一个数量级；
2. 算错的数字**看起来完全正常**：4.5 和 45 都是合理的泵速，屏幕不会报警；
3. 药物库的限值通常按"速率"设，浓度算错之后速率完全可能落在限值内。

所以这一篇的重点不是公式（公式很简单），是**怎么让每一步都可核对**。

## 标准换算流程

设医嘱剂量率为 D（μg/kg/min），患者体重 W（kg），药液浓度 C（μg/mL）。

第一步，算每小时需要的药量：

```
每小时药量 = D × W × 60        （单位：μg/h）
```

第二步，把药量换算成体积流速：

```
泵速 = 每小时药量 ÷ C          （单位：mL/h）
```

浓度 C 如果给的是"总药量/总体积"，先算：C = 总药量(μg) ÷ 总体积(mL)。
注意 1 mg = 1000 μg，这一步是最常见的错点。

## 一个完整例子

医嘱 `0.1 μg/kg/min`，体重 `60 kg`，药液 `4 mg / 50 mL`。

```
浓度   C = 4 mg ÷ 50 mL = 4000 μg ÷ 50 mL = 80 μg/mL
每小时药量 = 0.1 × 60 × 60 = 360 μg/h
泵速   = 360 ÷ 80 = 4.5 mL/h
```

反算验证：泵上设 4.5 mL/h，浓度 80 μg/mL，体重 60 kg：

```
每小时药量 = 4.5 × 80 = 360 μg/h
每分钟每公斤 = 360 ÷ 60 ÷ 60 = 0.1 μg/kg/min
```

能原路回到 0.1，说明没有哪一步把单位弄丢。**反算是自查的固定动作**，
比正算一遍再来一遍更能发现问题。

## 常见陷阱

**陷阱一：mg 和 μg。** "4 mg / 50 mL"如果被当成 "4 μg / 50 mL"，
浓度直接差一千倍。写浓度时带上单位，口头交代时不要只说数字。

**陷阱二：体重单位。** 部分泵要求 kg，如果按磅输入（或者反过来），
结果差约 2.2 倍。这个数字看起来仍然合理，不会触发任何报警。

**陷阱三：总量和浓度混着给。** "4 mg / 50 mL" 和 "80 μg/mL" 是同一个东西，
但前者容易在心算时忘了换算 mg→μg。建议统一先化成"每 mL 多少 μg"再往下算。

**陷阱四：质量单位 vs 生物学单位。** 胰岛素用 U（单位），不是 μg。
质量单位和生物学单位之间**没有**普适换算关系，两者混算没有意义。
看到 "U/h" 的医嘱，浓度也必须是 U/mL。

**陷阱五：算完不反算。** 正算两遍容易在同一个地方错两遍（尤其是一个人算）。
独立双人核对的意义就在这里：两个人**各自**从医嘱算到泵速，再对答案 `[依据等级 C：这是流程建议，各单位按本院制度执行]`。

## 配套工具

仓库里带了命令行和网页版的换算工具，纯算术，不联网，不需要索引：

```bash
# 剂量率 → 泵速
python -m infusion_rag.cli calc "0.1ug/kg/min" --weight 60 --conc 4mg/50mL --vtbi 50

# 泵速 → 剂量率（反算）
python -m infusion_rag.cli calc --rate 4.5mL/h --weight 60 --conc 4mg/50mL --as ug/kg/min
```

输出会把中间步骤一步步列出来：

```
剂量率   0.1 ug/kg/min
体重     60 kg
浓度     80 mg/mL（4 mg / 50 mL）

① 每小时所需药量 = 0.1 × 60 × 60 = 360 ug/h
② 泵速 = 360 ÷ 80 = 4.5 mL/h
③ 50 mL 输完约需 11 小时（约 667 分钟）

请在泵上设置后，按屏幕显示值与上面第②步的数字逐位核对。
```

这个推导过程本身就是双人核对时两个人要对的那张纸。

工具会拦下几类常见输入错误：剂量率带 /kg 却没给体重；剂量率不带 /kg
却给了体重（多半是没意识到单位输错）；质量单位和 U 混用；体积单位不是 mL。

网页版在检索界面下方，点开"剂量 ↔ 泵速 换算"即可。
