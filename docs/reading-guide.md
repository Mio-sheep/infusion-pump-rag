# 源码导读

写给两种人：想读这个仓库学点 Python 的初学者，以及接手维护的人。
按下面的顺序读，每一站都知道自己该看什么。

整个项目没有用任何第三方库，所有代码只依赖 Python 标准库。
这既是设计决定（见 [architecture.md](architecture.md)），客观上也让它
成为一份不含框架魔法的阅读材料——你看到的每一行都是 Python 本身。

## 先说读代码的方法

对每个文件按这四步走，比从头读到尾有效得多：

1. **只读文件开头的 docstring**。每个模块的第一段话讲清楚了它为什么存在。
2. **去 `tests/` 里找对应的测试文件**。测试是这个模块"应该怎么用"的活例子，
   `tests/test_bm25.py` 比 `bm25.py` 的正文更容易看懂。
3. **跑起来加打印**。用 `python -m infusion_rag.cli explain "阻塞报警"` 看中间结果，
   比盯着代码想直观十倍。
4. **改一行，看什么坏了**。把某个数字改掉，跑测试和评测，看哪些用例红了。
   这是理解"这段代码在防御什么"的最快方式。

## 阅读顺序

按依赖关系和难度排的，前面的是后面的一部分。

### 第一站：tokenizer.py（约 70 行）

**讲什么**：怎么把一段文字切成检索用的词。

**顺带的 Python 知识点**：正则表达式（`re` 模块）、字符串方法、列表推导式。

这一站值得花的功夫：看懂 `_LATIN` 和 `_CJK` 两个正则分别匹配什么，
为什么 `mL/h` 和 `IEC 60601-2-24` 不会被切碎。

### 第二站：config.py（约 90 行）

**讲什么**：所有可调参数集中在一处。

**知识点**：`dataclass` 装饰器、类型注解（`int`、`float`、`str | None`）、默认值。

这一站教你一个工程习惯：**配置和逻辑分开**。改参数不用翻代码。

### 第三站：frontmatter.py（约 140 行）

**讲什么**：解析文档头部那段 `---` 包起来的元数据。

**知识点**：字符串切分、`@dataclass` 定义数据结构、类方法（`from_dict`）、
`Optional` 值的处理。`_parse_block` 这个函数是一个小型**状态机**——
用几个变量记住"现在解析到哪了"，逐行推进。这种写法在解析类代码里到处都是。

### 第四站：synonyms.py（约 115 行）

**讲什么**：中英文同义词互相扩展，让"阻塞报警"和 "occlusion" 能互相找到。

**知识点**：字典和元组、集合的交并、函数拆分（`_present` 只干一件小事）。

### 第五站：chunker.py（约 300 行，全项目最费脑的一个）

**讲什么**：把一篇 Markdown 切成检索片段。

**知识点**：嵌套函数、生成器（`yield`）、`Path` 处理文件路径、多重条件分支。

建议分三次读：先读 `split_section`（怎么切文本），再读 `_split_table`
（表格为什么要单独处理），最后读 `parse_document`（怎么把前面这些拼起来）。
读不懂的地方，去 `tests/test_chunker.py` 里找对应的测试用例对照。

### 第六站：bm25.py（约 175 行）

**讲什么**：BM25 打分。文件开头的注释里有完整公式。

**知识点**：`collections.Counter`（数词频的神器）、`sorted` 的 key 参数、
浮点数累加、把数学公式逐句翻译成代码。

这是整个项目的心脏。看懂的标志：能回答"为什么标题和正文要分开算"。

### 第七站：store.py（约 130 行）

**讲什么**：索引怎么存成 JSON、怎么读回来。

**知识点**：`json` 模块、`dict` 和 `list` 的相互转换、版本号校验。

注意 `INDEX_VERSION` 那个检查：格式变了就拒绝加载旧索引，
宁可报错也不用错的数据算出看起来正常的结果。

### 第八站：retriever.py（约 200 行）

**讲什么**：把 BM25 和（可选的）向量检索融合起来排序。

**知识点**：类的组合（Retriever 拿着 index 干活）、`lambda`、
`@property`、异常的抛出与信息设计。

RRF 融合那十几行值得反复看——它回答了"两把量纲不同的尺子怎么合起来用"。

### 第九站：eval.py（约 150 行）

**讲什么**：评测集怎么变成 Recall 和 MRR。

**知识点**：多个 dataclass 互相引用、列表推导里嵌条件、
把一个数学定义（MRR = 名次倒数的平均）落成三行代码。

### 第十站：calc.py（约 250 行）

**讲什么**：剂量和泵速互相换算。

**知识点**：**输入校验和错误信息**（`CalcError` 的每条消息都是写给用户看的）、
正则解析用户输入、防御式编程（带 /kg 没给体重就拦下来）。

这一站教你的是工程里最值钱的习惯之一：**不信任输入，但用清楚的错误话术拒绝**。

### 第十一站：generator.py（约 150 行）

**讲什么**：把检索结果拼成提示词，调大模型接口。

**知识点**：`urllib.request` 调 HTTP 接口（不依赖 requests）、
异常的分门别类处理、字符串拼接成结构化文本。

### 第十二站：pipeline.py（约 210 行）

**讲什么**：把前面所有模块串成一条流水线。

**知识点**：`@classmethod`（`build` 和 `load` 两个入口）、
大型函数怎么按"步骤编号 + 日志"组织、字典作为返回值的接口设计。

到这里你已经能把整个项目从头到尾讲一遍了。

### 第十三站：cli.py（约 280 行）

**讲什么**：命令行入口。

**知识点**：`argparse` 的子命令、参数的默认值与类型、`main()` 的返回值即退出码。

### 第十四站（最难，最后看）：server.py（约 450 行）

**讲什么**：标准库 `http.server` 实现的网页版。

**知识点**：闭包（`_make_handler` 返回一个类）、类继承（`BaseHTTPRequestHandler`）、
在一个 Python 文件里内嵌 HTML/CSS/JS 字符串。

建议**只读 Python 部分**，内嵌的那一大段 HTML 当黑盒。

## architecture.md 值得单独读一遍

[architecture.md](architecture.md) 里写的是每个设计决定的"为什么"：
为什么 BM25 不用向量打底、为什么融合用 RRF、为什么中文用字符二元组。
**这些正是面试时会被问的问题**。代码读到哪里卡住，就回去翻对应的章节。

## 练习清单

读完之后做这几件事，每件都不难，但做完才算真的掌握了：

1. **加一组同义词**：在 `synonyms.py` 里加一个你自己领域的概念组，
   重新 `build`，用 `explain` 看查询 token 有没有变多。
2. **把 `heading_weight` 调成 0**，跑 `eval`，看 Recall 掉多少。
   这会让你直观理解"标题字段加权"值多少钱。
3. **给 `eval` 加一个新指标**：比如 Precision@3（前三条里正确的比例），
   照着 MRR 的写法抄一遍。
4. **给 CLI 加一个参数**：比如 `--no-synonyms`，让某次检索关掉扩展。
   改 `cli.py` 一处、`retriever.py` 一处。
5. **写一个新测试**：找一个没被覆盖的分支（比如 `parse_dose` 拒绝 "5L/h"），
   在 `tests/test_calc.py` 里补一个用例。

做完第 1、2 条，你就比大多数"看过 RAG 教程"的人理解得深了。

## 卡住了怎么办

提 issue 是对外的方式；本地调试时优先用这两招：

- `python -m infusion_rag.cli explain "你的查询"` —— 看分词和打分中间结果
- `python -m unittest tests.test_bm25 -v` —— 单跑一个测试文件，
  配合在代码里加 `print()`，是最朴素也最有效的调试方法
